# Phase 0 maintenance risks

This register separates Phase 0 evidence from checks proposed for later work. `COVERED` means a relevant automated test exists; it does not prove compatibility with a live Linux client. `PARTIAL` means tests cover only adjacent behavior. `MANUAL-SUPERVISED` requires a person to judge the result. `NOT COVERED` means no relevant test was found. P0 status is evidence at this pinned baseline, not a claim that a test was run during this documentation task.

## Severity and order

Severity: **critical** can corrupt protocol interpretation, credentials, or character actions; **high** can stop login, harvesting, or recovery; **medium** impairs maintenance or diagnosis. Implement detection first: (1) same-version platform/build identity, (2) mapping plausibility and field audit, (3) auth/schema compatibility, (4) asset and Cpp2IL compatibility, (5) Linux config restore and relay startup/crash recovery.

**Stop before P1** if the installed binary/metadata identity is not pinned per platform; protocol mapping audit fails or has unexplained low-confidence fields; login/auth cannot be replayed against a reviewed, sanitized capture; asset extraction is incomplete; the relay cannot start without privileged-port assumptions; or client redirect restoration has not been manually accepted on Linux. Never run an unreviewed mapping against a live character.

## Phase 0 evidence boundary

Verified Phase 0 evidence: the final suite passed 1,202/1,202 with `--max-parallel-test-modules 1`; `D3B.Network.Tests` passed 112/112. Linux client build 3.7.12.12 is Unity 6000.3.16f1, metadata v39, with `GameAssembly.so`. Extraction produced `data-8.pack` (26,870,514 bytes; SHA-256 `fdd6e182a62308ef9d4d7d92a3a0e157c864d3c5784f85ebad64234bb5a1e175`) and input fingerprint `2d869168d5a44e3828a153e530b06264291883be712d3b2963784b3139c00390`. The 170,287-byte schema SHA-256 is `e383c947b2c916c10d28636f73ebed0edfe556c61c3403dacf879b215be7e0b0`; repeated explicit and automatic runs matched. Cpp2IL preview 2022.1.0-pre-release.21 opened the Linux client. The earlier `mew: field 1 is written 0 times` schema failure was caused by interpreting SysV x64 writer arguments as Microsoft x64 registers; the ABI-aware register handling and order-independent tag/writer matching resolved it. Windows schema generation after stricter matching and real Linux relay/config crash acceptance remain unverified and MANUAL-SUPERVISED. Relay defaults include privileged port 443; captures may contain private data. These are recorded Phase 0 facts, not checks newly run here.
